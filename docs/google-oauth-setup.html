Google setup for Agni plugins

Two paths, no verification needed for either. Gmail uses an app password (requires 2FA on the account). Calendar and Drive use OAuth with sensitive scopes (scope justification only, no demo video, no weeks of review).

Why this exists: Google's only two doors are 2-Step Verification (app passwords) or an OAuth client in a Cloud project. We chose OAuth so the agent's mailbox needs no 2FA. The price is this one-time setup.

Why two paths: Gmail full access via OAuth requires Google verification (demo video, weeks of review). To skip that, Gmail uses an app password (needs 2FA on the account — Google's rule, satisfying "unless Google requires it"). Calendar and Drive use OAuth with sensitive scopes only (scope justification text, no demo video, no weeks of review).

Part 1 — Gmail app password (5 minutes, no Cloud Console, no verification)

A1Enable 2-Step Verification on the agent's mailbox.
  1. Sign in to myaccount.google.com/security with hey.agnibot@gmail.com.
  2. Under "How you sign in to Google", click 2-Step Verification → Get started.
  3. Follow the prompts. Save the backup codes somewhere safe.

Google requires 2FA for app passwords — this is Google specifying it, satisfying your rule. 2FA stays on forever.

A2Create an app password.
  1. Go to myaccount.google.com/apppasswords.
  2. App name: Agni → Create.
  3. Google shows a 16-character code (e.g. abcd efgh ijkl mnop). Copy it.
A3Put it in .env and restart. 
GMAIL_USER=hey.agnibot@gmail.com
GMAIL_APP_PASSWORD=abcd efgh ijkl mnop

Restart the daemon (bun run daemon restart). The Gmail plugin shows as Connected in Settings → Plugins. No Cloud Console, no verification, no demo video.

For your own mailbox too, repeat A1-A3 with your account and set GMAIL_OWNER_USER + GMAIL_OWNER_APP_PASSWORD.

Part 2 — Calendar & Drive via OAuth (sensitive scopes, no verification, no demo video)

1Create a Google Cloud project.
  1. Open console.cloud.google.com/projectcreate.
  2. Project name: agni (or anything). Leave Organization blank.
  3. Click Create. Wait for it to finish, then select it from the project dropdown at the top.
2Enable the three APIs Agni uses.
  1. Go to APIs & Services → Library.
  2. Search and Enable each: Google Calendar API, Google Drive API. (Gmail uses app passwords, not the API — no need to enable Gmail API.)
  3. (Skip any you do not want; the plugins for disabled APIs simply fail to connect later.)
3Configure the OAuth consent screen.
  1. Go to APIs & Services → OAuth consent screen.
  2. User type: External → Create.
  3. App name: Agni. User support email: your email. Developer contact: your email. Save and continue.
  4. Scopes → Add or remove scopes. Add these exact scopes: 
    https://www.googleapis.com/auth/calendar
https://www.googleapis.com/auth/drive.readonly
https://www.googleapis.com/auth/drive.file
https://www.googleapis.com/auth/userinfo.email
    Save and continue.
  5. Test users: skip (you are publishing to production in the next step, so anyone can consent).
  6. Branding page (left sidebar): fill in Application home page and Application privacy policy link with the two Google Sites URLs from step 3b. Save. (This is the field Google was complaining about.)
  7. Summary → Back to dashboard.
3bCreate a free homepage + privacy policy (Google requires these to publish).

Google now refuses to publish an External app unless it has a public homepage and a public privacy policy. You do not need to buy a domain — use Google Sites, which is free and lives on a Google-owned domain that needs no verification.

  1. Open sites.google.com → + Blank.
  2. Title the site Agni. Add one line of text (e.g. "Agni — personal assistant"). Click Publish → choose a web address like agni-home → Publish. Your homepage URL is now https://sites.google.com/view/agni-home.
  3. In the same site, click Pages → + New page → name it Privacy Policy. Add a short statement, e.g. "Agni stores your Google account tokens on your own daemon. They are never sent to anyone else. You can disconnect at any time from the app's Settings → Plugins pane." Publish again.
  4. Copy both URLs (homepage + privacy policy page).

If Google Sites is rejected as an authorised domain (rare), the fallback is a custom domain you own, verified in Google Search Console — but try Google Sites first; it works for the large majority of personal apps.

  1. On the OAuth consent screen page, find Publishing status and click Publish app.
  2. Confirm the dialog. The status changes from "Testing" to "In production".
  3. Google will warn about sensitive/restricted scopes and verification. For a personal app this is expected and harmless — proceed. (Verification is only required to remove the warning screen and the 100-user cap; neither blocks you.)

Do not skip this step. A project left in "Testing" issues refresh tokens that die after 7 days, and Agni's whole point is to connect once and forget.

5Create the OAuth client ID (Desktop app).
  1. Go to APIs & Services → Credentials → Create credentials → OAuth client ID.
  2. Application type: Desktop app. Name: Agni desktop.
  3. Click Create. A dialog shows your Client ID and Client Secret — copy both now.
  4. Open the client ID you just created and, under Authorized redirect URIs, add exactly: 
    http://127.0.0.1:8787/oauth/callback
    (Replace 8787 with your AGNI_PORT if you changed it.) Save.
6Put the credentials into Agni's .env. 
GOOGLE_OAUTH_CLIENT_ID=<paste client id>
GOOGLE_OAUTH_CLIENT_SECRET=<paste client secret>

Restart the daemon (bun run daemon restart) so it picks them up.

7Connect from the app.
  1. Open Agni → Settings → Plugins.
  2. Gmail (Agni's and yours): already connected if GMAIL_USER + GMAIL_APP_PASSWORD are in .env. Click Connect to verify.
  3. Calendar & Drive: click Connect. Your browser opens Google's consent screen. Click Advanced → proceed once (the "unverified app" interstitial), then grant. The browser lands on a plain "connected" page; close the tab. The app's plugin row flips to Connected.
  4. Repeat for each account (Agni's mailbox and yours are separate grants — sign out of one Google account in the browser between them, or use the account chooser).

What you get after this

  • Agni's Gmail — full autonomy: search, read, draft, send, label. No approvals.
  • Your Gmail — search/read/draft direct; sends ask you first.
  • Calendar (both accounts) — search always; creating events and inviting people asks first on your account.
  • Drive (yours) — search/read direct; creating and sharing asks first.
  • Granola + Notion — connect via the same Plugins pane (MCP, browser sign-in, no Cloud project needed beyond this one).

Limits on the record

  • 100-user cap on the unverified project — irrelevant for a personal assistant, but if you ever host Agni for others they share this cap (and the interstitial).
  • Tokens die if unused 6 months or if you change the account password or revoke — reconnect from the pane to recover.
  • Restricted-scope interstitial re-appears if Google changes its policy; reconnect fixes it.
